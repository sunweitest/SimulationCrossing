# 数据库表结构

> 库：PostgreSQL 16，库名 `simulation_crossing`，用户 `novel_user`（密码在服务器 `backend/.env` 的 `DATABASE_URL` 里）。
> ORM 定义：`backend/app/models/models.py`（SQLAlchemy，字段用 `Column()` 写法）。
> 本文按**实际库结构**核对过（`information_schema`），与模型一致。

## 0. 总览

| 表 | 规模 | 作用 |
|---|---|---|
| `users` | 小 | 账号（邮箱/手机 + 密码哈希） |
| `game_sessions` | 中 | 一局游戏 = 一条（角色快照 + 当前场景 + 累计状态） |
| `scene_history` | 大（每行动 +1） | 每回合生成的场景正文与选项 |
| `choice_history` | 大（每行动 +1） | 玩家实际做出的选择与得分 |
| `novel_configs` | 7 | 世界（小说/朝代）配置 |
| `timeline_configs` | ~51 | 某世界下的时间节点 |
| `preset_characters` | 95 | 预置角色 |
| `character_timelines` | ~193 | 预置角色 × 时间节点 → 初始场景/背景 |
| `alembic_version` | 1 行 | 迁移版本号，**别手动改** |

```
users ─┬─ game_sessions ─┬─ scene_history
       │                 └─ choice_history
       └─(游客: user_id NULL)

novel_configs ── timeline_configs
preset_characters ── character_timelines
```

## 1. `users` — 账号

| 字段 | 类型 | 可空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | int | 否 | 序列 | 主键 |
| `email` | varchar | 是 | — | 唯一；与 phone 至少填一个（**业务层校验，库里没约束**） |
| `phone` | varchar | 是 | — | 唯一 |
| `hashed_password` | varchar | 否 | — | bcrypt 哈希（`core/security.py`） |
| `is_active` | boolean | 是 | true | 置 false 后登录被拒 |
| `created_at` | timestamp | 是 | now() | **北京时间**（`app/core/timeutil.now_cn()`），无时区 |

唯一索引：`ix_users_email`、`ix_users_phone`。删用户会级联删其 `game_sessions`（ORM 层 `cascade="all, delete-orphan"`，不是数据库级联）。

## 2. `game_sessions` — 一局游戏

| 字段 | 类型 | 可空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | int | 否 | 序列 | 主键，前端 `/game/:id` 用的就是它 |
| `user_id` | int | **是** | — | 游客为 NULL；登录后由 `_claim_anonymous_session()` 补上 |
| `session_id` | varchar | 是 | — | 给 LLM 侧用的会话标识（uuid），唯一；与 `id` 无关 |
| `character_name` / `_gender` / `_age` / `_rank` / `_background` | varchar/int/text | 部分是 | — | **建局时的角色快照**，之后成长不改这里 |
| `novel` | varchar | 否 | — | 世界名，对应 `novel_configs.name`（字符串匹配，非外键） |
| `timeline` | varchar | 否 | — | 时间节点，对应 `timeline_configs.name` |
| `character_type` | varchar | 是 | — | 预置 / 自建（前端可能存中文标签） |
| `points` | int | 是 | 0 | 当前积分 |
| `achievements` | json | 是 | `[]` | **字符串数组**，如 `["穿越开始","随机应变"]`，只追加 |
| `current_scene` | json | 是 | — | 最近一回合的完整场景，结构见第 9 节 |
| `running_summary` | text | 是 | — | 长对话压缩后的故事概要 |
| `summary_turn_count` | int | 否 | 0 | 已压缩到第几轮（压缩游标，防重复压缩） |
| `characters_state` | json | 是 | — | 结构化人物追踪，结构见第 9 节 |
| `created_at` / `updated_at` | timestamp | 是 | now() | 北京时间（`now_cn()`）；`updated_at` 有 `onupdate`，每次保存自动刷新 |

索引：`ix_game_sessions_id`、`ix_game_sessions_session_id`（unique）。
**缺索引**：`user_id` 没有索引，「我的存档」按它过滤是全表扫描。

## 3. `scene_history` — 场景流水

| 字段 | 类型 | 可空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | int | 否 | 序列 | 主键 |
| `game_session_id` | int | 否 | — | → `game_sessions.id`（外键，已建索引） |
| `turn_index` | int | 否 | 0 | 回合序号，0 = 开局，之后每次行动 +1；回溯/配对都靠它 |
| `scene_description` | text | 否 | — | 该回合生成的正文 |
| `choices` | json | 是 | — | 该回合生成的选项（字符串数组） |
| `points_awarded` | int | 是 | 0 | 本回合加分 |
| `achievement` | varchar | 是 | — | 本回合解锁的成就（单个，可能 NULL） |
| `scene_image` | varchar | 是 | — | 本回合配图 URL，回溯时用来还原 `current_scene` |
| `created_at` | timestamp | 是 | now() | 北京时间 |

一个 `game_sessions` 行对应 N 条；压缩历史时按 `created_at` 取旧记录。

## 4. `choice_history` — 玩家选择流水

| 字段 | 类型 | 可空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | int | 否 | 序列 | 主键 |
| `game_session_id` | int | 否 | — | → `game_sessions.id`（外键，已建索引） |
| `turn_index` | int | 否 | 0 | 与 `scene_history.turn_index` 对齐，回答「这一回合玩家选了什么」 |
| `choice` | text | 否 | — | 玩家输入或点选的选项原文（自定义输入也算一条） |
| `points` | int | 是 | 0 | 该次行动得分 |
| `created_at` | timestamp | 是 | now() | 北京时间 |

两张流水表靠 `turn_index` 配对（同一回合的选择与场景序号相同）。

## 5. `novel_configs` — 世界配置

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | int | 否 | 主键 |
| `name` | varchar | 否 | 唯一，如「三国演义」「明代」；`game_sessions.novel` 存的就是这个字符串 |
| `description` | text | 是 | 一句话简介，前端卡片副标题 |
| `sort_order` | int | 是 | 展示顺序（升序） |
| `created_at` | timestamp | 是 | UTC |

## 6. `timeline_configs` — 时间节点

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | int | 否 | 主键 |
| `novel_id` | int | 否 | → `novel_configs.id`（外键，**无索引**） |
| `name` | varchar | 否 | 节点名，如「黄巾起义」「赤壁风起」 |
| `description` | text | 是 | 简介 |
| `sort_order` | int | 是 | 顺序 |
| `created_at` | timestamp | 是 | UTC |

## 7. `preset_characters` — 预置角色

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | int | 否 | 主键 |
| `novel` | varchar | 否 | 世界名（**字符串，不是外键**），有索引 |
| `name` | varchar | 否 | 角色名；`(novel, name)` 无唯一约束，可能重复 |
| `gender` / `age` / `rank` | varchar/int/varchar | 是 | 性别 / 年龄 / 身份 |
| `background` | text | 是 | 默认背景（某节点下会被 `character_timelines.background` 覆盖） |
| `starting_points` | int | 是 | 初始积分 |

后台支持 xlsx 批量导入：`/api/admin/character-template` 下载模板 → `/character-import` 上传。

## 8. `character_timelines` — 角色 × 时间节点

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | int | 否 | 主键 |
| `character_id` | int | 否 | → `preset_characters.id`（外键，**无索引**） |
| `timeline` | varchar | 否 | 时间节点名（对应 `timeline_configs.name`） |
| `background` | text | 是 | 该节点下的角色背景（覆盖 preset 的） |
| `initial_scene` | text | 否 | **开局正文**，建局时直接写入 `current_scene`，不调 LLM |

这就是「开局零成本、零延迟」的原因：开局文本是配置好的，第一次行动才真正调模型。

## 9. JSON 字段结构

### `game_sessions.current_scene`（= `Scene` schema）

```json
{
  "scene_description": "你站在…（正文，可含 \\n）",
  "choices": ["选项1", "选项2", "选项3", "选项4", "选项5"],
  "game_update": { "points_awarded": 7, "new_achievement": "随机应变" },
  "scene_image": "/images/scene/两军交战突袭.png"
}
```

- `scene_image` 可能为 `null`（没匹配到图，或没配 `DASHSCOPE_API_KEY`）
- 新建会话时这里存的是 `character_timelines.initial_scene`（纯文本）或兜底文案，此时**没有 choices / game_update** —— 前端必须判空

### `game_sessions.characters_state`

```json
{
  "characters": [
    {
      "name": "曹操",
      "identity": "兖州牧",
      "relationship_to_player": "主公",
      "favorability": 35,
      "status": "存活",
      "last_interaction": "第 3 回合召见你",
      "first_appeared_turn": 2
    }
  ],
  "last_updated_turn": 6
}
```

- 由 `context_compressor.extract_characters()` 在**压缩时**顺带生成，不是每回合更新
- `favorability` 范围 -100~100；读取时会补 `favorability_label` 用于 prompt 展示
- 只有被压缩进摘要的人物才会进来，早期人物可能缺失

### `game_sessions.achievements`

```json
["穿越开始", "随机应变"]
```

纯字符串数组，追加式，无上限、无去重。

## 10. Redis（不算库，但属于状态存储）

| key | 类型 | TTL | 含义 |
|---|---|---|---|
| `rate_limit:user:<id>:<YYYY-MM-DD>` | string(int) | 86400s | 登录用户当日已用次数 |
| `rate_limit:user:<id>:extra` | string(int) | 无 | 后台加的额外次数，用一次减一 |
| `rate_limit:user:<id>:unlimited` | string | 无（人工设置） | 存在即包月不限次 |
| `rate_limit:guest:ip:<ip>:<YYYY-MM-DD>` | string(int) | 86400s | 游客当日已用次数（按真实 IP） |

规则出处只有 `backend/app/services/quota.py`，`middleware/rate_limit.py` 负责检查与 +1。
**清 `rate_limit:*` 等于清掉所有人当天额度**，线上有人玩时别清。

## 11. 迁移与改表

```bash
cd /opt/novel/SimulationCrossing/backend
/opt/venv/bin/alembic revision --autogenerate -m "add xxx"   # 改完 models.py 后生成
/opt/venv/bin/alembic upgrade head
```

- 迁移文件在 `backend/alembic/versions/`；`alembic_version` 表只有一行
- **基础内容数据（世界 / 时间线 / 角色）不在迁移里**，是后台录入或 `pg_dump --data-only` 灌的；换机器时两条路要分开做
- 加列要设默认值或允许 NULL，否则老数据会卡住 `NOT NULL`

## 12. 已知结构问题（维护时注意）

| 问题 | 影响 | 建议 |
|---|---|---|
| ~~外键列没索引~~ | 已于迁移 `62366e48b269` 修复：5 个外键 + `(session, turn)` 复合索引 | — |
| ~~两张流水表无显式配对~~ | 已加 `turn_index`，并据此实现回合回溯 | — |
| ~~时间用 UTC 导致 8 小时偏差~~ | 已改为北京时间写入（迁移 `62366e48b269` 平移了历史数据） | 仍需注意：库里是 naive 时间，做跨时区部署要重新评估 `timestamptz` |
| `preset_characters` 的 `(novel, name)` 无唯一约束 | 同名角色可能重复出现在列表里 | 后台录入时校验 |
| `achievements` 无去重、无上限 | 长期对局 JSON 越滚越大 | 追加前判重 |
| 删用户靠 ORM 级联 | 直接 `DELETE FROM users` 会外键报错（流水表还引用会话） | 先删流水再删会话/用户，或走 ORM |
| 没有软删除 / 审计字段 | 误删不可恢复 | 重要表可加 `deleted_at` |
